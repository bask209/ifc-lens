# License compliance

**Policy:** the viewer and everything it ships to browsers are Apache-2.0. The only other runtime components are browser-native APIs (WebGL2, Web Workers, Custom Elements, Streams, `DecompressionStream`).

> A package's top-level SPDX license is not enough for this project. Release compliance is evaluated against the actual browser artifacts and every source/runtime component that contributes to them.

## What ships

- `package.json` has an empty `dependencies` object and no peer, optional or bundled dependencies.
- `dist/` is produced by the TypeScript compiler (Apache-2.0) from `src/`, targeting ES2022 with `importHelpers: false` and `noEmitHelpers: true`, so the compiler injects no runtime helpers.
- No bundler is used, so no bundler runtime can enter the artifact.
- Every source file carries `SPDX-License-Identifier: Apache-2.0`.

## Components deliberately not used

| Candidate | Finding | Decision |
|---|---|---|
| `@babylonjs/core` 9.27.1 | Apache-2.0 manifest, but the package NOTICE lists MIT *meshoptimizer*. The import closure of a minimal viewer subset (engine, scene, camera, mesh, material, light, ray: 252 modules) includes `tslib.es6.js`, a copy of Microsoft's 0BSD tslib | Not used. The project ships its own WebGL2 renderer |
| `manifold-3d` / Manifold WASM | Apache-2.0 core, but the browser build is generated by Emscripten, whose emitted JS/runtime is MIT/NCSA; the npm package also declares unrelated runtime dependencies | Not used. The project ships its own mesh Boolean engine |
| earcut and similar triangulators | Not Apache-2.0 | Not used. Project-owned ear-clipping triangulator |
| web-ifc, IFC.js / That Open, IfcOpenShell, xeokit | Excluded by policy | Not used, not consulted; the implementation follows the public IFC specification semantics |

The buildingSMART IFC specification is used as reference material only. No schema files, documentation text or schema-generated tables are included. Entity and attribute names appear in hand-written decoders.

## The gate (`npm run audit:licenses`)

1. `package.json`: no runtime/peer/optional/bundled dependencies; license `Apache-2.0`.
2. Every file in `dist/` must be one of the expected artifact types. No `node_modules` paths are allowed.
3. **Provenance**: every emitted `.js` file must have a source map, and every `sources` entry must resolve to a file under `src/` that carries the Apache-2.0 SPDX header. Anything else fails the build. This is authoritative.
4. **Secondary alarms**: `dist/` must contain no bare-module imports, and no third-party license texts or markers (MIT/ISC/BSD/MPL/GPL phrases, `tslib`, `meshoptimizer`, excluded package names).
5. **Development dependencies**: every installed package is inventoried with its license. Non-Apache development packages must be on the documented exception list:

   | Package | License | Why it is acceptable |
   |---|---|---|
   | `@types/node` | MIT | Type declarations for type-checking tests and scripts; never shipped |
   | `undici-types` | MIT | Dependency of `@types/node`; type declarations only |

   All other development dependencies (`typescript`, `@typescript/typescript-*`, `@playwright/test`, `playwright`, `playwright-core`) are Apache-2.0.

The audit writes `dist/build-provenance.json` (compiler version, commit, SHA-256 and source list of every emitted file) and `COMPLIANCE.json`. `npm run verify:package` re-runs the audit on the unpacked `npm pack` tarball, because only the tarball is what consumers receive. `npm run sbom` writes a CycloneDX 1.5 SBOM: the shipped files with hashes, plus the development packages with `scope: excluded`.

## Test data

The compatibility suite downloads the buildingSMART Certification-datasets (CC BY 4.0, © buildingSMART International Ltd.) at a pinned commit into a cache directory. The files are not vendored, not committed and not packaged. All fixtures committed to this repository, including the demo model, are generated by `scripts/generate-fixtures.ts` and are Apache-2.0.

## Upgrades

Any new dependency, or an upgrade of `typescript` or Playwright, must pass the gate. Adding a runtime dependency requires changing the policy in this document first.
